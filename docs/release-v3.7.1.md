# v3.7.1 — 手機日期欄「凸出去」真正的修法（iOS 原生控制項）

發佈日期：2026-09-27
線上版本：<https://competition-manager-hazel.vercel.app>

## 問題

使用者在 v3.6.8 之後回報：日期欄「**還是凸出**」，但「**點擊正常**」。

## 為什麼 v3.6.8 的修法沒用（誠實檢討）

v3.6.8 判斷根因是「`min-width: auto` 撐破 grid 格子」，因此在原生控制項與包裝層都加了 `min-width: 0`。
**這個判斷在 iOS 上不成立**：iOS 的原生日期欄不吃 `min-width: 0`，仍然畫在自己的內在寬度上。
而本機檢查跑 Chrome（內在寬度小），那條結構斷言**永遠是綠的**——等於沒守到，這才是真正該檢討的地方。

這次先用**可重現**的方式量出來：在 402px 下把日期欄的內在寬度模擬成 iOS 實測的 343px
→ 重現使用者截圖（比賽開始／結束凸出 22px、報名開始／截止凸出 35px）。

## 修法：外框由包裝層負責

- `.cm-date-wrap`（包裝層）負責**框線／圓角／底色／裁切**：`overflow: hidden`＋`border: 1px solid var(--cm-bd-300)`＋`background-color: var(--cm-field)`。
- 原生控制項本身 `border: 0`：凸出的部分被包裝層裁掉，框一定留在卡片內。
- 焦點環改畫在包裝層（原生控制項自己的 ring 會被裁掉）。
- **沒有動 `-webkit-appearance`**：點擊照樣叫出日期轉盤（使用者已確認點擊正常，這個行為不動）。
- 深色模式跟著主題走（實測深色下框線 `rgb(71,85,105)`、底色 `rgb(22,35,58)`）。

**實測**：模擬 iOS 343px 時，外框超出由 **+22／+35px → −1／−14px**；把內在寬度加到極端的 520px 也不凸。

## 新增守門（這次才真的擋得住回歸）

`tests/browser/mobile-layout-check.js` 在 402px 加上三類斷言（該支由 83 → **100 項**）：

1. **★模擬 iOS 內在寬度 343px** 後，每個日期欄的外框仍必須在卡片內。
2. **外框契約**：包裝層要有框線且 `overflow: hidden`；原生控制項本身 `border-width: 0`（否則凸出時框會少一邊）。
3. **★命中測試**：在外框右緣外 2px 的位置**不得命中原生日期欄**（＝凸出的部分真的被裁掉，與肉眼所見等價）。

**RED 驗證**：把「裁切＋包裝層框線」拿掉後 → **88 通過 / 12 失敗**（第 3 類斷言回報命中 `input#date`，正是使用者的症狀）；還原後 **100 通過 / 0 失敗**。
