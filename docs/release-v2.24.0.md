# v2.24.0 — 賽事複製與週期性賽事

**發佈日期**：2026-09-26｜**類型**：P1 賽事與報名核心（Roadmap P1-4）

## 為什麼要做

辦比賽的人一年到頭在做同一件事：開一場新賽事，把上一場的地點、時間、分類、隊伍設定、報名窗、審核與候補規則**再填一次**。每週三的例賽、每兩週的積分賽、每月的排名賽更是如此——內容幾乎一樣，只有日期往後推。

這一版就是把這件事自動化：**一鍵複製既有賽事**，以及**設定週期讓系統自己排下一場**。

## 一鍵複製賽事

- 每張賽事卡片（管理員）新增「📄 複製賽事」。按下去確認後，立即產生一場新賽事。
- 名稱一律加「（複製）」；已經是複製品的不會變成「（複製）（複製）」。
- **照抄的**：地點、日期、時間、結束時間、說明、分類與標籤、隊伍設定（是否團體／每隊人數／名額／報名截止）、報名開始與結束時間、需審核、開放候補、遞補通知開關。
- **不搬的**：報名紀錄、隊伍、海報檔案——複製品是乾淨的新場次，不會把上一場的參賽者帶進去。
- 複製品**不帶週期設定**：手動複製是一次性的，不會被每日排程當成某個系列的一員。
- 留稽核紀錄（動作：複製賽事），內容寫明從哪一場複製到哪一場、日期、以及「報名與隊伍不搬」。

## 週期性賽事（每週／每兩週／每月）

- 賽事卡片新增「🔁 週期」：設定重複方式（每週／每兩週／每月）與「重複到哪一天」（留空＝一直重複）。設定完成後，卡片按鈕會直接顯示目前週期（例如「🔁 每兩週」）。
- 兩個建立管道，走**同一份**判斷規則：
  - **每日排程**：現有的每日 cron（`/api/cron/reminders`，Vercel 每天 01:00 UTC）除了推播提醒，順便看每個系列該不該開下一場。不需要另外設定排程。
  - **面板上的「⬇️ 立即建立下一場」**：不用等排程，按了馬上看結果。
- 規則（白話寫在面板裡，後端與介面共用同一份純函式）：
  - 下一場日期＝目前系列最後一場往後推一個週期；**每月**遇到當月沒有那一天時夾到月底（1/31 → 2/28，不跳過那個月）。
  - 只會**提前 30 天內**才建立，不會一年前就把整年的場次開出來。
  - **一次只排一場**：系列裡只要還有「今天以後」的場次，就不會再往後疊。
  - 新場次沿用同一個名稱、繼續同一個系列，**報名開始與結束時間一起往後挪**同樣的天數（免得新場次的報名窗還停在舊日期）。
  - 超過「重複到哪一天」就停；如果推算出的下一場已經過期（例如排程很久沒跑），不會偷偷補一堆，而是回報「週期已落後」請你手動處理。
- 週期是**整個系列**的設定：改其中一場，同系列其他場次一起同步（介面會回報同步了幾場）。
- 稽核動作：設定賽事週期、週期性賽事建立下一場（後者由排程觸發時操作者記為 `system`）。

## 資料庫

需要執行 `migrations/2026-09-26-v2.24.0-recurrence.sql`（三個欄位＋一個部分索引，可重複執行）：

| 欄位 | 用途 |
|---|---|
| `competitions.recurrence` | `weekly`／`biweekly`／`monthly`／null |
| `competitions.recurrence_until` | 重複到哪一天（null＝一直重複） |
| `competitions.recurrence_parent_id` | 系列第一場的 id（判斷「這個日期是否已排過」） |

**沒有執行 migration 時**：複製賽事照常可用；週期設定與「立即建立下一場」回 503 並告訴你要跑哪個檔；每日排程不會因此壞掉（週期性部分回報未啟用）。
