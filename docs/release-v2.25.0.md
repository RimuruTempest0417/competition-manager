# v2.25.0 — 推播時間與事件可設定（＋修好頁面上方的版本號）

**發佈日期**：2026-09-26｜**類型**：P2 通知與溝通（Roadmap P2）

## 為什麼要做

推播一直是「系統說了算」：每天固定 01:00（UTC）＝澳門時間 09:00 發一次，而且只有「即將開賽」與「新發布賽事」兩種，管理員想改時間、想暫時關掉某一類通知，只能改程式再部署。

另外還有一個很實際的問題：**頁面上方「發佈與管理各類賽事資訊 (v2.18.0)」的版本號從 v2.18.0 之後就沒再更新過**——因為它是寫死在 HTML 裡的。

這一版把兩件事一起處理：推播的**時間與事件都可在面板設定**，版本號**改由後端帶入**，並加上測試讓它不能再忘記。

## ⏰ 推播設定（管理員以上）

導覽選單新增「⏰ 推播設定」，一個面板管完：

| 設定 | 說明 |
|---|---|
| 每日摘要 | 總開關。關掉就完全不發摘要（即時通知不受影響） |
| 摘要發送時間 | 澳門時間，預設 `09:00`。過時會補發一次，一天只發一次 |
| 摘要要包含哪些事件 | 「新發布的賽事」「即將開賽提醒」可各自開關 |
| 即時通知的事件 | 「報名審核結果（核准／未錄取）」「候補遞補通知」可各自開關 |

- 按「儲存設定」後畫面直接回報**每一項的前後變化**（例如「發送時間：09:00 → 21:30、摘要含新賽事：開啟 → 關閉」），並回讀一次確認畫面與資料庫一致。
- 設定存在既有的 `app_settings` 鍵值表，**不需要 migration**。
- 留稽核紀錄（新動作：更新推播設定），每一項的前後值都記下來。
- 「即時通知」的候補遞補開關與**每場賽事**的「遞補通知開關」是兩層：站台這層關掉就完全不打擾，賽事層管的是「這一場要不要通知」。

## 一天只發一次、時間到就補發

- 伺服器每天檢查兩次（Vercel cron 01:00／13:00 UTC＝澳門 09:00／21:00）。**只有「當地日期還沒發過、而且已經過了設定的時間」才真的發**，並記下最後發送日期，所以不會因為檢查兩次就重複發。
- 設定的時間若在兩次檢查之間（例如 18:00），當天 21:00 那次會補發一次——寧可晚一點，不要漏掉。
- 沒有訂閱者、沒有到期的賽事、或事件全被關掉時，排程會明確回報原因（`digest.reason`），不是靜悄悄地什麼都沒做。

## 關掉的事件是真的關掉

- 被關掉的即時通知**連推播訂閱都不會查**（不是查了才不送），流程本身照常運作：報名審核照樣核准、遞補照樣生效、稽核照樣記錄。
- 讀不到設定（例如資料庫少了 `app_settings` 表）時，**一律視為全部開啟**：情願多發也不要漏發，並在面板上以提示說明目前的降級狀態。
- 推播這一段失敗（憑證、資料表問題）也不讓整個排程倒下：稽核清理與週期性賽事照做，失敗原因照實回報。

## 版本號不再忘記改

- 頁面上方副標改由 `GET /api/version` 帶入（單一來源＝`package.json`），HTML 不再寫死版本。
- 新增守門測試 `tests/version-consistency.test.js`：`package.json` 版本＝`<title>` 版本、頁面不得再出現寫死的 `(vX.Y.Z)`、副標必須由 `/api/version` 更新、`/api/version` 回的值要等於 `package.json`。以後版本不一致會直接讓測試紅燈。
- 真 Chrome 檢查也加了一條：頁面上方副標顯示的版本必須等於後端版本，且不再是 `v2.18.0`。

## 資料庫

**不需要 migration**。`app_settings` 表若不存在：讀設定回預設值並標記 `schema_ready:false`（附說明），寫設定回 503 並說明，排程仍以預設值運作。
