# v2.27.1 發佈說明

**主題**：把「按鈕隱形」這類問題納入自動檢查（只加檢查與文件，沒有改動功能）

- **日期**：2026-09-26
- **版本**：v2.27.1
- **migration**：無

---

## 一、為什麼要發這一版

使用者回報「公告中心也是這種錯誤」——**公告中心的「發布公告」按鈕同樣看不到**，與推播設定的「儲存設定」是**同一個根因**（`bg-sky-600` 這個色系在 `tailwind.min.css` 與 `custom.css` 都不存在 → 白字配透明底＝隱形）。v2.27.0 已經把 26 處 `sky-*` 全部改成專案既有的 `blue-*`，**但當時只有推播設定那顆按鈕有自動檢查**，公告中心靠運氣（覆蓋率腳本剛好也會涵蓋，但沒有針對「按鈕看不看得見」的斷言）。

這一版把守門補齊：**只要按鈕的底色是透明的、或文字顏色與底色相同（＝看不見），測試就會失敗。**

---

## 二、這一版做了什麼（全部是檢查與文件）

1. **新增 `tests/browser/live-style-check.js`**：對**正式站**用真實 Chrome 算過 CSS 後檢查
   - 四顆送出按鈕（推播設定「儲存設定」、公告中心「儲存訂閱」／「發布公告」、工作人員「指派／更新」）**有底色且文字與底色不同**；
   - 兩顆連結式按鈕（「全部標記已讀」、「＋ 發布新公告」）**不是白色文字**；
   - 全頁掃描「**文字顏色＝底色**」的隱形文字（回報前 10 筆）。
   - 已納入 `npm run check:prod`（`check:prod` ＝ 煙霧測試 ＋ 訪客視角 ＋ 線上樣式檢查）。
2. **公告中心介面檢查**（`announcements-check.js`）新增 4 項按鈕可見性斷言（真 Chrome、管理員已登入）。
3. **工作人員介面檢查**（`venue-staff-check.js`）新增 1 項「指派／更新」按鈕可見性斷言。
4. **修正線上樣式檢查的按鈕 id**（`submitAnnounceBtn`，第一次寫成 `announceSubmitBtn` 導致誤判「按鈕不存在」）。

## 四、根因回顧（避免重犯）

| 層次 | 問題 | 現在的防線 |
|---|---|---|
| 直接原因 | 按鈕用 `bg-sky-600`，該色系在 CSS 裡不存在 → 白字配透明底 | 26 處改用 `blue-*`（v2.27.0） |
| 為什麼沒被發現 | 顏色 class 覆蓋率腳本只在開發機、且色系白名單漏了 `sky` | 腳本進 repo、白名單補 `sky`、`accent-*` 納入掃描，並由 `tests/class-coverage.test.js` 在 `npm test` 執行（v2.27.0） |
| 為什麼「本機測過」還是漏 | 本機檢查只驗「元素存在／文字正確」，沒算過 CSS | 新增按鈕可見性與隱形文字斷言，並在**正式站**也跑（v2.27.1） |
