# v2.26.0 — 推播失敗可視與重送＋站內公告／訊息中心

**發佈日期**：2026-09-26｜**類型**：P2 通知與溝通（Roadmap P2 收尾）

## 為什麼要做

推播到現在只留下「成功發了幾則」，**失敗幾則、為什麼失敗、原本要送什麼給誰**全都看不到——訂閱過期、推播服務擋掉，管理員只能從「使用者說沒收到」才知道出事，而且沒有任何補救手段（只能等下一次排程）。

另外，Email 通知已確定不做，站上缺少一個**可以對特定對象說一句話**的地方：場地異動、器材盤點、內部提醒，只能靠推播（訂閱者才收得到、沒有已讀紀錄、看不到歷史）。

這一版補上這兩塊：**推播失敗看得見、可以重送**；**站內公告／訊息中心**成為通知的正式管道。

## 📤 推播失敗可視與重送（管理員以上）

「📤 推播紀錄」現在每一筆都會顯示：

| 顯示 | 說明 |
|---|---|
| 成功／失敗則數 | 失敗的紀錄以紅框標示 |
| 失敗原因 | 例如 `HTTP 410`、`HTTP 500`（最多記 500 字） |
| 送出的內容 | 當時的標題（重送用的就是這份內容） |
| 重送紀錄 | 已重送幾次、最後一次時間、那次成功幾則 |
| 重送按鈕 | 「重送給原本的對象」 |

- **重送只送給原本的對象**：單一使用者的通知只送他那筆訂閱；公告這類多人通知只送當初名單上的那些人（不是全站廣播）。
- 重送是**手動指令**，不受「⏰ 推播設定」的自動通知開關影響（設定管的是「系統自動發什麼」，管理員按下去就是要送）。
- 重送會把**重送次數、時間、成功則數寫回同一筆紀錄**，並留稽核紀錄（新動作：重送推播），稽核內容寫明送給誰（`限使用者 #91`、`限 2 位使用者`、`所有有效訂閱`）。
- 訂閱回應 `404／410`（裝置已失效）的，重送時順手把該訂閱標記為失效，之後不再重複打它。
- 沒有內容可重送的舊紀錄（v2.26.0 之前的紀錄只記筆數），按重送會明確回 400 說明「沒有可重送的內容」，不會假裝成功。

## 📣 站內公告／訊息中心

導覽選單新增「📣 公告中心」，**登入即可看到**（一般使用者也能用）：

- **未讀徽章**：選單按鈕上直接顯示未讀數（99 以上顯示 `99+`），點公告卡片即標記已讀，另有「全部標記已讀」。
- **我訂閱的公告分類**：勾選自己有興趣的分類（與賽事分類同一套 10 類）並儲存，儲存後立刻反映在「看得到哪些公告」。
- **管理員以上**多一塊「管理公告」：發布／編輯、置頂、預約發布時間、設定結束時間、上架／下架（下架只是不顯示，資料保留），以及**每一則的已讀人數**（例如「已讀 3/12」）。
- 發布時可勾「同時發送推播」：只推給**符合對象的使用者**的訂閱；站台層的「推播設定 → 站內公告發布通知」關掉時，公告照發、推播跳過並說明原因。

### 對象與可見性規則

| 對象 | 誰看得到 | 誰收到推播 |
|---|---|---|
| 所有人 | 所有登入者 | 所有訂閱者 |
| 管理員以上 | 管理員以上 | 管理員以上的訂閱者 |
| 特定分類訂閱者 | 訂閱到該分類的人 | 訂閱到該分類的人的訂閱 |

**管理員在訊息中心一律看得到全部上架中的公告**（剛發布的分類公告如果自己看不到，會以為發布失敗）；但**通知（推播）仍嚴格照對象送**，沒訂閱該分類的管理員不會被通知到。

可見性與時間規則（上架中、尚未到發布時間、已過結束時間）是**前後端共用的同一份純函式** `public/js/announcements.js`（後端直接 `require`），避免前後端各寫一套造成「列表看得到、點進去說無權」。
