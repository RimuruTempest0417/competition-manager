## 一、這版解決什麼問題

系統原本的流程只走到「報名 → 審核 → 賽事當天」就斷了：賽事辦完，成績沒有地方放，
主辦只能另外開一份試算表，參賽者也看不到自己第幾名。

v3.1.0 把最後一段接起來：

```
報名 → 審核 → 賽事當天 → 登錄成績（草稿）→ 公布 → 參賽者看到名次
```

## 二、三個角色看到什麼

**管理員**：賽事卡片多一顆「🏆 成績登錄」

- 名單自動帶出這場賽事**已核准**的報名（未審核、已拒絕、已取消的人不會出現在名單裡）
- 每列填：成績（自由文字，如 `12:34.56`、`85`、`3–2`）、狀態、名次、備註
- 「🔢 自動排名」一鍵把名次算好：時間類用「越小越好」，分數類用「越大越好」
- 「💾 儲存草稿」：前台看不到，可以慢慢核對
- 「🏁 公布結果」：可勾選同時推播通知參賽者；公布後仍可修改並重新公布
- 「↩️ 取消公布」：退回草稿（成績不會被刪掉）

**參賽者**：已公布的賽事多一顆「🏆 成績」，以及「我的報名」裡多一行成績

- 成績表：前三名領獎台（🥇🥈🥉）、完整名次表、自己的那一列被標記「（你）」
- 「我的報名」直接顯示：`🏆 成績：🥈 第 2 名 · 12:30`
- 可以匯出成績 CSV（沿用既有的 CSV 模組，含公式注入防護）

**訪客**：看得到已公布的成績（比賽結果本來就是公開資訊）；未公布時只會看到「成績尚未公布」。

## 三、規則與設計取捨

- **名次怎麼算**：只有「完賽」且成績看得懂（時間或數字）的人會進名次；
  未完賽／未出賽／取消資格一律不排名（名次顯示「—」）。
- **不會把看不懂的成績當 0**：`未完成`、`3–2`、`85 分` 都不會被解析成數值，因此不會被排成第一名。
- **並列名次**：同分同名次（1, 1, 3），這是真實比賽的常態，所以 `rank` 刻意**不設唯一鍵**。
- **公布前檢查**（只提示、不擋人）：還缺幾位參賽者的成績、名次重複、名次跳號。
  並列之後的跳號（1,1,3）不算異常，只有「上一個名次沒並列卻跳號」才提醒。
- **草稿不外洩**：`result_published_at` 是「前台看不看得到」的唯一依據；
  未公布時，訪客與一般使用者拿到的是 `{ published: false, results: [] }`，
  連統計數字也不會給（避免從統計反推出誰第幾名）。
- **規則的唯一真實來源**：`public/js/results.js`（UMD）——後端驗證、前端選單／排名／顯示、測試
  用的是同一份程式，不會出現「畫面上第 2 名、API 說第 3 名」。
- **推播是站台層開關**：新增「賽事成績公布通知」設定（預設開啟）；
  關掉只是不通知，成績照樣公布。只推給有報名的參賽者。

## 四、API

| 方法 | 路徑 | 權限 | 說明 |
|---|---|---|---|
| GET | `/api/competitions/:id/results` | 公開（管理員可看草稿） | 已公布的成績、統計、前三名 |
| GET | `/api/competitions/:id/result-sheet` | 管理員以上 | 登錄用：已核准名單＋成績＋公布前檢查 |
| PUT | `/api/competitions/:id/results` | 管理員以上 | 批次儲存（可 `auto_rank`／`order`、`remove_ids` 明確刪除） |
| POST | `/api/competitions/:id/results/publish` | 管理員以上 | 公布（需 `confirm: true`，可 `notify: true`） |
| POST | `/api/competitions/:id/results/unpublish` | 管理員以上 | 取消公布（需 `confirm: true`） |
| GET | `/api/my/results` | 已登入 | 我的成績（只有已公布、只有自己的） |

稽核動作：`SAVE_RESULTS`（登錄成績）、`PUBLISH_RESULTS`（公布成績）、`UNPUBLISH_RESULTS`（取消公布）。

## 五、安全與資料一致性

- 儲存成績前**整批驗證**：名次不是正整數、報名不屬於本賽事、未核准的報名、同一筆重複送出，
  一律回 400 並列出哪幾列有問題，且**一筆都不會寫入**（不會留下半套成績）。
- 公告式的保守設計：公布／取消公布都要 `confirm: true`；刪除要明確送 `remove_ids`，沒送就一筆都不刪。
- 新資料表開啟 RLS 且不開放 anon（與其他表一致）；伺服器端一律用 service_role。
- 未執行 migration 時：成績端點回 503 並附檔名，其餘功能完全不受影響（賽事、報名、審核照常）。
