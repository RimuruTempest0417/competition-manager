# v3.6.3 — 賽事取消／延期＋卡片最新消息

> Roadmap 8.8⑥。颱風延期、場地臨時不能用是常態，而係統原本的賽事狀態**完全由日期推導**：
> 「延期過」「取消」算不出來，臨時變更只能靠推播——但推播要訂閱，沒訂閱的人什麼都看不到。

## 這版做了什麼

**管理員（賽事卡片 →「📣 公告／取消」）**

| 動作 | 效果 |
|---|---|
| ⛔ 取消賽事 | 填原因（必填）後取消：卡片標示「⛔ 賽事已取消」＋原因，**立刻不能報名**（按報名會被擋下並顯示取消原因） |
| 復原 | 取消時間與原因一起清掉，恢復原本狀態 |
| 🕒 延期 | 選新日期／時間：卡片標示「🕒 賽事延期至 …（原訂 …）」，延期期間**暫停報名**；可「取消延期標記」還原 |
| 📣 最新消息 | 集合時間、場地更換等臨時公告，**不需訂閱推播**就看得到；可清空 |

**所有人**：取消／延期／最新消息直接顯示在賽事卡片上（紅／琥珀／藍三色區分），詳情與報名視窗同步可見。

## 設計決定（為什麼這樣做）

1. **原訂時間絕不覆蓋**：延期另存 `postponed_date`／`postponed_time`，`date`／`time` 保持原值——
   事後查得到「原本訂幾號、後來延到幾號」。想改日期是另一件事（編輯賽事），兩者不混用。
2. **人工狀態優先於日期推導**：取消／延期由 `public/js/competition-state.js`（前後端共用的唯一來源）判斷，
   排在日期邏輯**之前**——否則「日期還沒到」會讓已取消的賽事顯示成「報名中」。
3. **取消與延期一律停止報名**：變動期間讓人搶名額沒有意義，而且會讓名額對不上帳；
   只填「最新消息」則不影響報名。
4. **公告畫在卡片上、不依賴推播**：這是 8.8⑥ 的核心——推播要訂閱，臨時變更最需要人人看得到。
   （取消時的一鍵推播公告屬加分項，需要先決定「賽事公告」是否成為站台推播開關，本版未做。）
5. **公告內容一律跳脫**：管理員輸入的文字直接進 HTML 會出事，卡片與彈窗都走 `escapeHtml`。

## 資料庫

`migrations/2026-09-27-v3.6.3-cancel-postpone-news.sql`（已套用，可重複執行）：

```
competitions.cancelled_at    timestamptz  -- 取消時間（null＝未取消）
competitions.cancel_reason   text         -- 取消原因（顯示在卡片）
competitions.postponed_date  date         -- 延期後的新日期
competitions.postponed_time  text         -- 延期後的新時間（HH:MM）
competitions.news            text         -- 最新消息
competitions.news_updated_at timestamptz  -- 消息更新時間
```

沒跑 migration 時三個端點都回 **503** 並指出要跑哪一支（不會假裝成功）。

## API

| 端點 | 權限 | 說明 |
|---|---|---|
| `POST /api/competitions/:id/cancel` | 管理員以上 | `{reason}` 取消；`{cancelled:false}` 復原。取消必填原因（400） |
| `POST /api/competitions/:id/postpone` | 管理員以上 | `{postponed_date,postponed_time}` 延期；`{postponed_date:null}` 取消延期。日期要真實存在、不可與原訂相同（400） |
| `POST /api/competitions/:id/news` | 管理員以上 | `{news}` 更新（上限 300 字）；空字串＝清空 |

稽核：`CANCEL_COMPETITION`／`POSTPONE_COMPETITION`／`UPDATE_COMPETITION_NEWS`（已登記進 `AUDIT_ACTIONS`）。
