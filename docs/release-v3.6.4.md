# v3.6.4 — 賽事公告的一鍵推播（8.8⑥ 加分項）

> v3.6.3 讓公告「不訂閱也看得到」；這版把另一半補上：**要推播的人，一鍵就推得到**。

## 這版做了什麼

**管理員（賽事卡片 →「📣 公告／取消」）**

彈窗上方多一個勾選框（**預設勾選**）：

> ☑ 同時推播通知**已報名者**（下方三個動作都會套用）
> 沒訂閱推播的人一樣會在賽事卡片上看到公告，關掉站台開關則完全不推。

勾著送出後，系統會：

| 動作 | 推播內容 |
|---|---|
| ⛔ 取消 | 「⛔ 賽事取消：<賽事名>」＋「原訂 2026-10-05 09:00｜原因：颱風來襲，場地封閉」 |
| 🕒 延期 | 「🕒 賽事延期：<賽事名>」＋「延至 2026-11-15 08:30（原訂 2026-10-05 09:00）」 |
| 📣 最新消息 | 「📣 <賽事名> 公告」＋公告全文（清空消息不會推播） |
| 復原／取消延期 | 也會推播「恢復原訂時間」的訊息（同樣要勾選） |

送出後的回覆會直接寫清楚結果，例如：
**「已更新最新消息（卡片上會直接顯示），已推播給 12 位已報名者（實際送到 9 個裝置）」**

**推播設定頁**新增一個站台開關：**「賽事公告通知（取消／延期／最新消息）」**。關掉後，
即使管理員勾了推播也不會送，而且會回報 **「未推播（站台設定已關閉「賽事公告通知…」）」**——
不會讓人以為送出去了。

## 設計決定

1. **只推給真的有報名的人**：賽事公告的對象就是報名者。推播是「通知」，亂槍打鳥會讓推播變成噪音
   （線上目前只有 5 個帳號、0 筆有效報名——精準比量大重要）。
2. **軟刪除的報名不算對象**：自己取消報名的人不該再收到該賽事的推播（`is_deleted` 過濾）。
3. **兩個開關都要開才會送**：站台層（推播設定頁）＋這次的勾選框。這是既有的兩層慣例
   （v2.25.0 起「站台開關」與「每賽事通知」兩層），只是這版的第二層改成「每次送出時決定」。
4. **推播失敗不影響主要動作**：取消／延期／更新公告本身一定要成功；推播結果（送幾個裝置、
   幾個失敗）另外記進 `push_log`，失敗不拋錯、不回滾。
5. **計數誠實**：`sent` 是「實際送出的裝置數」、`targets` 是「打算通知的人數」。
   沒有人訂閱時 `sent = 0`，回覆會寫「（對方尚未訂閱推播）」，不假報成功。

## 過程中修掉的假紅燈

全量瀏覽器檢查第一次跑時 `waitlist-extra-check.js` 有一項失敗（「說明文字改成『不通知』」）：
該檢查在資料庫寫入後**立刻**讀畫面文字，但畫面重繪是非同步的（要等 `loadTeams` 回來），
偶爾會讀到舊文字。已改成輪詢等待（最多 8 秒），單獨重跑與全量重跑都綠。
這不是本版功能造成的，但留著會讓以後每版都遇到假紅燈。
