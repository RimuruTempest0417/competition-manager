# v3.2.0 發佈說明

**主題**：名單列印版（P1-7）——現場要用的那張紙

- **日期**：2026-09-26
- **版本**：v3.2.0
- **新增**：`public/js/printdoc.js`（列印規則）、`public/css/print.css`（列印樣式）、列印預覽視窗

---

## 一、為什麼要做這個

系統到 v3.1.0 為止，資料都只在螢幕上：報名名單要現場點名、成績要在布告欄貼出來，
主辦只能自己截圖、複製貼上到 Word，或是手抄。這一版把「**印出來的那張紙**」變成系統的一部分。

## 二、怎麼用

**列印報名名單**（管理員以上）：賽事卡片 →「🖨️ 列印名單」

- 紙上自動帶：賽事名稱、時間（含結束時間）、地點、類別、列印時間、摘要句（共幾人／正取幾人／候補幾人／尚餘幾個名額）
- **預設只把「已錄取」放進正取名單**；候補自成一段並標示「候補 1、候補 2」（依遞補順位），
  不會被誤當成要點名的人
- 可切換：**包含候補**、**包含待審核**（現場補位用）、**簽到欄**（手寫打勾的地方）、**橫向**
- 未錄取與已取消的人**不會印出來**（那不是現場要用的名單）

**列印成績表**（任何人，限已公布的賽事）：賽事卡片 →「🖨️ 列印成績」，
或成績視窗裡的「🖨️ 列印成績表」

- 名次、姓名、成績、狀態、備註；並列名次照原值印（1、1、3），未到場顯示「—」
- 摘要句：共幾筆／完賽幾筆／已排名幾筆

**列印方式**：預覽視窗按「🖨️ 列印 / 另存 PDF」→ 用瀏覽器列印（可另存 PDF）。
列印時**只會印出那張紙**，App 的按鈕與清單都不會出現在紙上。

## 三、實作上的幾個決定

- **規則唯一真實來源 `public/js/printdoc.js`（UMD）**：預覽、列印、測試共用同一份，
  所以「預覽看到的」與「印出來的」不會不一致。
- **樣式放在 `public/css/print.css`**，不是 inline `<style>`——CSP 是 `style-src 'self'`。
  列印時用 `@page { size: A4 }`，並隱藏 `body` 底下除了列印視窗以外的一切。
- **表頭每頁重複**（`thead { display: table-header-group }`）、單列不跨頁（`page-break-inside: avoid`）。
- **螢幕預覽會依裝置寬度縮放**（手機也看得到完整版面），實際列印固定 A4；
  列印方向也可以在瀏覽器列印對話框裡再調整。
- **不連外**：列印版不含任何外部資源（CSP 只允許 `'self'`），也不放圖。
- **紙本會離開系統**：列印內容不含 email、密碼、雜湊或 token，只有姓名／隊伍／成績等現場必要資訊。

## 四、測試

**單元測試 `tests/printdoc.test.js`（16 項）**：只印已錄取、候補順位排序、未錄取不印、
摘要句與紙上內容一致（沒印候補就不說有候補）、簽到欄可關、團體賽多印隊伍欄、
名次排序（無名次排最後顯示「—」）、惡意名字被轉義、不引入外部資源。

**瀏覽器檢查 `tests/browser/print-check.js`（32 項，真 Chrome 手機尺寸）**：

| 驗什麼 | 怎麼驗 |
|---|---|
| 列印按鈕存在與權限 | 管理員有名單列印；一般使用者沒有；已公布才有成績列印 |
| 紙上內容 | 賽事資訊、列印時間、摘要句、列數＝正取＋候補、候補順位、未錄取不出現 |
| 選項即時生效 | 取消候補→候補段消失且摘要句不再提候補；勾待審核→出現；關簽到欄→表頭改變 |
| 列印真的被呼叫 | `window.print` 恰好一次 |
| **列印樣式真的有效** | 用 CDP `Emulation.setEmulatedMedia('print')` 切到列印媒介，實測工具列與 App 主體 `display: none`、紙張仍可見 |
| **真的產出 PDF** | `Page.printToPDF` 產生 241 KB、開頭 `%PDF-` 的檔案內容（**只取回內容，不寫任何檔案到磁碟**） |
| 成績表 | 名次原值（1,1,3）、狀態與成績都在、不提供「包含候補」選項 |
| 個資 | 紙上沒有 email／密碼／雜湊／token |
| 手機 | 無橫向溢出、無前端例外、沒有下載任何檔案 |
