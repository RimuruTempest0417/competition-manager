## 一、為什麼要做

1. **地點只有一行文字**：卡片寫「澳門氹仔運動場」，但外地選手要自己複製到地圖 App 查。既有的舊賽事也不可能一筆筆補連結。
2. **現場人員分工無處可記**：誰是裁判、誰負責記錄與攝影，過去只能靠群組訊息或口頭，賽事當天沒人能查。
3. **（順手修掉）推播設定的「儲存設定」按鈕看不見**：使用者反映「確認按鈕沒有顯示（可能在關閉旁邊）」。原因是按鈕用了 `bg-sky-600`——**這個色系在專案的 Tailwind 靜態檔與 custom.css 裡都不存在**，於是白字配透明底＝整顆按鈕隱形，只剩旁邊的「關閉」。同時把「顏色 class 覆蓋率檢查」搬進 repo 並納入 `npm test`，避免同類問題再靜默上線。

## 二、這一版做了什麼

### 📍 場地地圖連結

- 賽事表單新增「**地圖連結 (選填)**」欄位；卡片地點旁多一個「**🗺️ 地圖**」連結（另開新頁、`rel=noopener`）。
- **沒填就用地址自動產生** Google 地圖搜尋連結，並標示「（用地址搜尋）」——所以**舊賽事不用補資料**，一上線就有地圖可按。
- 有填就以自訂連結為準（例如 `maps.app.goo.gl/...`、`www.google.com/maps/...` 這種沒帶協定的會自動補 `https://`）。
- **安全與誠實**：只接受 `http／https`；`javascript:`、`data:`、或把地址整串貼進地圖欄位一律**回 400 並說明原因**（不靜默丟掉、也不偷偷建立賽事）。更新時「留空」＝清掉自訂連結、回到地址自動產生；「完全沒帶欄位」＝不動既有值。
- 複製賽事與週期性自動建立的下一場，都會沿用同一場地的地圖連結。
- 規則唯一真實來源：`public/js/venue.js`（UMD，前後端共用）。

### 🧑‍⚖️ 工作人員指派

- 每場賽事可指派工作人員，角色固定五種：**裁判／記錄／攝影／醫護／其他**（規則唯一真實來源 `public/js/staff.js`）。
- **同一場、同一人只有一個角色**：再指派一次＝改角色（不會變成兩筆）；改角色時稽核會寫出「裁判 → 攝影」的前後差異。
- 可加備註（最多 200 字，例如「第三場地」）；沒帶備註＝不動既有備註，帶空字串才清掉。
- **卡片徽章**「🧑‍⚖️ 工作人員 N」＋獨立面板：角色人數摘要、每列顯示「⚖️ 裁判 王小明（第三場地）」與「由誰指派」。
- **權限界線**：清單是**公開**的（賽事工作人員本來就是公開資訊，只回角色與帳號名稱，不含 email、權限或任何 token）；**指派與移除只有管理員以上**能做，且一律留稽核（`ASSIGN_STAFF`／`REMOVE_STAFF`，寫明賽事與對象）。
- 停用中的帳號不能指派；帳號被刪除時該筆指派仍會列出並顯示「（已刪除）」，不會在賽事當天少一個人。

### 🐛 修復：推播設定的「儲存設定」按鈕看不見

- 26 處 `sky-*` class 改為專案既有的 `blue-*` 主按鈕色（原本 `bg-sky-600` 沒有規則）。
- 一併補上 `hover:text-amber-900` 規則（變數本來就有、只缺 class 規則）。
- **根因防護**：`scripts/class-coverage.py` 搬進 repo、色系白名單補上 `sky`（原本漏了它才讓 `bg-sky-600` 沒被檢查到）、`accent-*` 也納入掃描，並新增守門測試 `tests/class-coverage.test.js` —— 以後 `npm test` 就會擋下「用了不存在的顏色 class」。
