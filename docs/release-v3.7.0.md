# v3.7.0 — 分享賽事（掃碼直接報名）＋ 權限介面修正 ＋ 示範流程腳本

發佈日期：2026-09-27
線上版本：<https://competition-manager-hazel.vercel.app>

## 這一版在解什麼問題

使用者走完手機示範流程後的回饋是：「**我覺得少用的原因可能是我找的使用者太少了**」。
自助註冊本來就是開放的（沒有邀請碼、同一 IP 每小時 5 次），門檻等於零；
真正的問題是**別人不會自己走到那個網址**。這一版把「把賽事傳出去」變成一顆按鈕，
並且讓收到連結的人**少走幾步就完成報名**。

## 一、分享連結與 QR（一掃就去報名）

- 賽事卡片新增 **「🔗 分享連結／QR」**，**訪客也看得到**（要分享的人常常還沒登入）。
- 彈窗內容：**QR 圖** ＋ **報名連結**（唯讀欄位）＋「📋 複製連結」＋「📋 複製賽事文字」。
- 連結刻意做短：`https://<站台>/#c<賽事編號>`（例如 `#c51`）。
  **為什麼要短**：QR 的網址越長、格子越密，低階手機鏡頭越容易掃不到。
- **QR 產生器擴充**：原本只支援容錯等級 M（版本 1–3，最多 42 bytes），
  分享網址約 49 bytes 塞不下 → 新增**等級 L**（版本 1–3，最多 53 bytes），等級 M 的行為完全不變。
  等級要同時改「資料碼字數」與**格式資訊位元**（L=01／M=00）；只改前者會畫得出來但**整張掃不到**。
- **驗證方式**：用 **macOS Vision（`scripts/qr-decode.swift`）當獨立解碼器**，
  對 `…/#c51`、`…/#c1234` 兩條真實連結解碼回原文——不用自己寫的解碼器自己驗自己。
- 介面上另外釘住：QR 必須用 `crispEdges` 畫（否則格子被糊掉就掃不到）、
  格子數必須與同一條連結的編碼一致、必須有無障礙標題。

## 二、深連結：掃碼進來直接到那場賽事

網址是 `…/#c<賽事編號>` 時：

1. 捲到那張卡片並**高亮 4 秒**（讓人知道要看哪裡）。
2. **未登入** → 帶出「請先登入或註冊帳號，才能報名參加比賽」的登入視窗
   （沿用既有規則，不是新行為）。
3. **已登入** → 直接開該賽事的報名視窗。
4. 已經開著的分頁被貼上分享連結時，也會跟著跳（`hashchange`）。

## 三、權限：沒有權限的人看不到發佈表單

發現於實測：**測試帳號看得到整份「➕ 發佈新比賽」表單**，一路填到送出才被後端 403 擋下——
介面在騙人，也浪費使用者的時間。根因是前端角色權限表把 `test` 的 `create` 寫成 `true`，
而後端 `POST /api/competitions` 只收管理員。

- 前端權限表：`test` 的 `create` 改為 `false`（`guest`／`user` 本來就是 `false`）。
- 新增**守門測試** `tests/permissions-ui.test.js`（3 項）：真的把前端那張表**解析出來**比對
  （不是比對原始碼字串）＋確認 `#createSection` 開站時是關的、可見性綁在 `perm.create` 上
  ＋確認後端發佈端點確實有角色守門。

## 四、順手修掉的三件事（實測時發現）

1. **兩個彈窗會疊在一起**：「我的報名」與「報名名單與隊伍編排」現在互相關閉，
   不會再出現上層蓋住下層、點了沒反應的狀況。
2. **候補／已核准數字停在舊值**：名單類動作（審核、簽到、取消簽到、遞補、取消報名）
   完成後自動重新載入，不必再手按「🔄 重新載入」。
3. **已簽到的報名不可直接取消**（`409`：請先「取消簽到」再取消報名）。
   原本可以在軟刪除的紀錄上留下「幽靈簽到」，也看不出是誰放掉名額；介面也同步不再提供按鈕。
   *保留不動*：取消報名仍沿用原生 `confirm()`／`alert()`——那是這個系統一貫的做法（共 20 多處），
   只改一處反而會不一致。

## 五、示範流程腳本

`scripts/demo-walkthrough.mjs`：把「自助註冊 → 看到示範賽事 → 報名（額滿自動排候補）→ 讀回我的報名」
在正式站跑一遍，可以重複執行。帳號密碼在記憶體中隨機產生、**不寫檔、不印出**，也不下載任何檔案。

## 升級注意

- **無資料庫結構變更**（這一版沒有 migration）。
