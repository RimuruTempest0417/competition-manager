# v3.2.1 — 版面空間優化（大螢幕不留白）

**一句話**：桌機原本一張 1198px 寬的賽事卡片，左邊的內容欄被右側按鈕區擠到只剩 **84px**（用不到 7%），
日期、人數、名額一行一行往下排，右半邊整片空著；1920 的螢幕主容器又固定只用到 1280px。
這一版把空間用起來，手機版同時保持好讀。

## 你看到的三種浪費，以及量到的數字

| 浪費 | 原因 | 修正前（實測） |
|---|---|---|
| 卡片左邊像一條細長的紙 | 卡片右側的按鈕區用「內容自然寬度」（約 1100px）跟左邊搶，左邊只剩殘餘空間 | 內容欄 **84 / 1198 px（7%）** |
| 日期、人數、名額各佔一行 | 原本是會自動換行的橫向排列，但寬度不夠就一直往下掉 | 卡片高 **612px** |
| 大螢幕右邊一大片空 | 主容器固定 `max-w-7xl`＝1280px | 1920 螢幕只用 1280px（**空 640px**） |

## 做法

1. **卡片右側的按鈕區限制寬度**：`max-width: min(30rem, 44%)`
   —— 固定值在平板（768～1023px）會把內容欄再擠扁（實測剩 28%），所以同時看比例：任何寬度下按鈕區都不超過卡片的 44%。
2. **資訊改用「自動欄數格狀」**：每個資訊至少 7.5rem，塞得下幾個排幾個
   —— 手機 2 欄、平板 2 欄、桌機 4 欄、大桌機 7 欄；不是靠截斷文字來塞滿。
3. **內容欄加 `min-width: 0`**，長字串（例如工作人員名單）不會把卡片撐破。
4. **大螢幕（≥1600px）容器放到 1560px**：真正用滿寬度，但不會變成讀不下去的長行。

## 前後對照（真實 Chrome 量測）

| 視窗 | 卡片內容欄 | 卡片高度 | 資訊欄數 | 主容器寬 |
|---|---|---|---|---|
| 手機 414 | 302（91%）→ **302（91%）** | 441 → **453**（+12，換來整齊的兩欄） | 1 → **2** | 414 |
| 平板 834 | —（擠壓）→ **382（51%）** | — → **255** | **2** | 834 |
| 桌機 1440 | 84（7%）→ **660（55%）** | 612 → **219** | 1 → **4** | 1280 |
| 大桌機 1920 | —（擠壓）→ **940（64%）** | — → **187** | 1 → **7** | 1280 → **1560** |

卡片高度在桌機少了約 **2.7 倍**（612 → 219），同一個畫面能看到的賽事多得多，而且每個欄位都還在原位。

## 手機沒有被犧牲

- 沒有橫向溢出；13 顆按鈕全部可見（實測 13/13），最小寬度 44px 仍好按。
- 資訊從「一行一項、長短不齊」變成兩欄對齊（地點／地圖、開始／結束、人數／名額…），更好掃視。
- 日期太長時是換行，不是截斷（實測資訊欄文字溢出 0 個）。
