# v2.23.0 — 候補收尾：多選一次搬多筆、異動紀錄可以往回翻

**發佈日期**：2026-09-26｜**類型**：P1 賽事與報名核心（Roadmap P1-2 第四輪補強）

## 為什麼要做

v2.22.0 給了拖拉與「第 N 位」下拉（一次搬一筆），但實際操作上還有兩個收尾沒做：

1. **一次搬多筆**：實務上很常出現「這三個人是一隊／同一批繳費的，一起往前排」。只能一筆一筆搬的話，搬第一筆就會讓其他人的位置跟著位移，管理員得邊搬邊重算，很容易搬錯。
2. **異動紀錄看不到更早的**：面板只顯示最近 30 筆（後端固定只抓最新 100 筆），賽事辦到中後期時，前面幾週「為什麼這個人排在那裡」已經查不到了——而這正是主辦最需要查的時候。

這一版把這兩個收尾補齊，其餘行為完全不變。

## 新增

### 1. 多選一次搬多筆

- 每一列左側多了**勾選框**（只有能手動排序時才出現）。勾選後下方出現批次列：**「已選 N 筆」**＋**「搬到 第 __ 位」**下拉＋**「搬過去」**＋**「清除選取」**。
- **搬完的相對順序＝名單上原本的相對順序**（不是照勾選的先後），所以結果可預期：勾了第 3、4 位一起搬到最前面，兩人前後關係不變。
- 「搬到第 N 位」的意思是**這批人的第一位會排在第 N 位**；一次搬 N 筆時，下拉的選項自動只到「人數 − N + 1」（例如 4 位候補選 2 筆，最多只能放到第 3 位）。
- 搬完（或重新整理名單）**勾選會自動清空、批次列收起**，避免管理員對著已經失效的勾選再按一次。
- 名單在勾選期間被別人改動 → 後端驗證（v2.21.0 的完整順序驗證）會整批拒絕並要求重新整理，**不會寫出半套結果**。
- 位置換算走共用純函式 `CMCompetitionState.moveGroup(ids, selectedIds, toIndex)`：批次的相對順序、夾到頭尾、重複勾選只算一次、有任何 id 不在名單就回 `null`（呼叫端不送 API）。

### 2. 異動紀錄可以往回翻

- 面板底部多了**「⬇️ 載入更早」**與一行說明：
  - 還有更早的 →「已顯示 30 筆」＋按鈕可按
  - 全部載完 →「已顯示全部 43 筆」＋按鈕自動收起
  - 到達上限 →「已顯示 500 筆（達 500 筆上限，更早的紀錄請到稽核日誌頁篩選）」
- 端點 `GET /api/competitions/:id/waitlist/history?limit=30&offset=30` 新增 `offset`／`has_more`／`capped`／`window_size`。
- 抓取窗口＝**這一頁結尾 + 1**（用來判斷「還有沒有更早的」），單場最多往回抓 **500 筆**（避免有人用 offset 無限翻）。
- 分頁保證**不重複、不漏**：兩頁合起來等於一次抓全部的結果（測試有驗）。
- 沿用與 `/api/audit-logs` 相同的寫法（抓一個窗口再自己切頁），所以正式站與測試替身的行為一致。

## 設計取捨（重點）

| 決定 | 理由 |
| --- | --- |
| 批次搬移**不是**重寫排序，而是把「新的完整順序」算好再送 `/waitlist/reorder` | 後端驗證（名單一致性）與稽核完全沿用，不必新增端點或新的不變量；一次搬多筆與搬一筆走同一條路。 |
| 批次保持「名單上的相對順序」而不是「勾選順序」 | 名單順序就是目前的名次；用勾選順序會出現「我明明由上往下勾，結果順序卻反了」這種不可預期的結果。 |
| 一次搬 N 筆時限制目標位置（只到 人數 − N + 1） | 最後 N 位不可能塞下 N 個人；與其送出後被後端拒絕，不如下拉就不給選。 |
| 搬完自動清空勾選 | 名單重繪後舊勾選已經沒有意義（位置全變了），留著只會誤按。 |
| 分頁用「抓窗口再切」而不是 `range(offset, offset+limit)` | 這是專案既有慣例（`/api/audit-logs` 的理由相同）：正式站 PostgREST 依 range 回傳、測試替身回全部，這樣寫兩種環境行為才一致。 |
| 上限 500 筆而不是無上限 | 單場賽事的候補異動不會多到 500 筆；真的有更早的需求，稽核日誌頁有完整的篩選與匯出，沒必要在彈窗裡重造一套。 |
| 前端不自己記「已載入到第幾筆」以外的狀態 | 每次載入都是以伺服器回來的資料為準；`loaded` 只用來顯示說明文字，畫面上的筆數就是真相。 |

## 已知限制

- 批次搬移**一次只能指定一個目標位置**（沒有「把 A 搬到 B 前面」這種相對插入）。
- 勾選狀態**不會跨重新載入保留**（換句話說：關掉彈窗再開就要重勾）。
- 異動紀錄單場最多顯示 500 筆；更早的紀錄請到「稽核日誌」頁面用賽事／動作篩選（那裡有匯出）。
- 批次搬移**不會通知**被移動的人（只有真的被遞補才通知，且仍受 v2.22.0 的「遞補通知」開關控制）。
