# v3.9.2 — 修「回顧報告／系列總積分按鈕失效」（CSP 擋掉行內事件）＋ 新增「🧪 示範流程」按鈕

發佈日期：2026-09-27

## 一、修好了：彈窗按鈕按下去沒反應（你回報的那個）

**現象**：回顧報告與系列總積分的「✕」「關閉」按鈕按下去沒反應，彈窗關不掉；「📋 複製文字摘要」與內文那顆「🏆 看這個系列的總積分」也一樣。

**真因**：CSP 是 `script-src 'self'`（沒有 `'unsafe-inline'`），瀏覽器會用 `script-src-attr` **直接擋掉行內事件屬性**。
v3.9.0 那一版我用了 6 個 `onclick="…"`，全部被擋 —— 按鈕看起來完全正常，按下去卻什麼都不會發生，而且**單元測試與當時的瀏覽器檢查都不會發現**（檢查是用 `CMReview.open()` 直接開彈窗，從來沒按過那些按鈕）。

用探針實測到的證據（本機）：

```
script-src-attr ｜ inline        ← 點了關閉鈕之後，瀏覽器回報的就是這一行
```

**修法**：全部改成 `addEventListener`／事件委派（動態產生的按鈕用 `data-series-root` ＋ 委派），CSP 不放寬。
**同一個病因還有一個**：系列總積分的積分長條圖寬度是用 `style="width:63%"` 寫的 → `style-src-attr` 也會擋掉，長條根本不會依分數長短變化；改成 `.cm-bar-0`～`.cm-bar-10` 類別。

**守門（避免再犯）**：新增 `tests/no-inline-handlers.test.js`
- 掃 `public/` 底下所有 `.html` 與 `.js`：**不准出現行內事件**（onclick／onchange／onsubmit／onerror…）
- 也不准出現**行內 `style` 屬性**（同一類 CSP 問題，樣式會安靜失效）
- 並釘住回顧報告／系列彈窗的按鈕 id 與綁定確實存在（沒有綁定就等於按鈕是啞的）
- 瀏覽器檢查也補上：四個關閉鈕真的按得動、複製摘要真的送出文字、長條寬度真的依分數不同、**整個流程零 CSP 違規**

## 二、新增：管理員專屬「🧪 示範流程」按鈕（你要的一步步手動測試）

位置：右上角選單 → **🧪 示範流程**（管理員／超級管理員／網站擁有者才看得到）。

彈窗裡有七步，**每一步都可以單獨按**，按完會自動讀回狀態並顯示做了什麼：

| 步驟 | 內容 |
|---|---|
| ① 建立示範第一站 | 建立「【示範】秋季系列 第一站」（含系列積分 10/8/6/5…） |
| ② 設定每週週期 | 讓第一站成為一個「系列」（系列積分才成立） |
| ③ 由週期建立第二站 | 用系統的週期功能產生第二站並改名 |
| ④ 兩場報名 | 第一站 4 人、第二站 5 人（多一位只在第二場出賽） |
| ⑤ 登錄成績 | 依名次給分；第二站 2 位未完賽（超表＝0 分但仍在榜上） |
| ⑥ 公布成績 | 公布後訪客才看得到成績與系列積分 |
| 🗑️ 清除示範資料 | 把所有「【示範】」賽事連同報名／成績移除 |

- 進度顯示「N / 6」，做過的步驟會變 ✅ 並寫出 id、日期、人數等實際結果；已經做過的不會重複建立。
- 另有「▶ 一鍵跑完 ①～⑥」（一步失敗就停，讓人看清楚問題在哪）、「🔄 重新讀取狀態」、
  「🏆 看系列總積分」「📊 看第一站的回顧報告」可直接跳過去看結果。
- **只呼叫既有的正式 API**（建立賽事／週期／週期下一場／現場代報名／登錄成績／公布／刪除），
  沒有為了示範另開後門端點；每個動作都會照原本的規則寫進操作日誌。
- 名稱一律帶「【示範】」字樣，方便辨識與清除。

## 三、順手修掉的測試工具問題

`tests/support/fake-supabase.js` 的唯一鍵模擬在**鍵值為 NULL** 時誤判衝突（現場代報名沒有 `user_id`，
第二位之後會被誤判成「已經有報名紀錄」）。真實 Postgres 的唯一索引**NULL 彼此不相等**，
已照這個語意修正 —— 這也是為什麼以前沒有檢查能覆蓋「連續現場代報名多筆」。
