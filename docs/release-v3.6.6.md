# v3.6.6 — 手機版位修正（使用者回報）

> 使用者 2026-09-27 用手機看系統（截圖 804px 寬 ÷ 2 ＝**402px** 視窗），回報「顯示狀態並不理想」。
> 這一版先把「實際壞掉」的位置修好，並把量測變成常駐檢查——不是靠眼睛看。

## 先量測再改（實測數字）

| 位置 | 修正前 | 修正後 |
|---|---|---|
| 「發佈比賽」按鈕 | **14×149px**（被壓成「一個字寬」的直排細條，就是截圖右邊那條藍色直條） | **320×40px**（整條好按） |
| 「報名開始／截止」欄位 | 兩欄並排，390px 時每欄只剩 **135px**（值會被截掉，iOS 更容易溢出卡片） | 手機單欄 **282px**，值完整可見 |

## 根因

1. **按鈕被壓扁**：`<div class="flex gap-2">` 這一列同時裝「上傳海報區塊」與送出按鈕，按鈕是 `flex-1`。
   在窄螢幕上它被壓到 **min-content 寬度＝一個中文字寬**，於是中文直排成一條細線。
   → 改成手機上下堆疊（`flex-col sm:flex-row`），海報區塊 `min-w-0 sm:flex-1`，
   按鈕 `w-full sm:w-auto shrink-0 whitespace-nowrap`（`shrink-0` 讓它永遠不會再被壓扁）。
2. **兩欄日期欄位**：`grid grid-cols-2 gap-3` 少了響應式前綴（同檔案其他網格都有 `sm:`／`md:`）。
   `datetime-local` 在手機上的最小寬度大於半個卡片，因此被壓扁或溢出。
   → 改 `grid-cols-1 sm:grid-cols-2`（手機單欄、≥640px 才兩欄）。
3. **空白框**：`<input type="date">` 不能有 placeholder，而它旁邊沒有任何標籤。
   → 加可見標籤（桌機也更清楚）＋`aria-label`。

## 新增常駐檢查：`tests/browser/mobile-layout-check.js`

既有的 `layout-check.js` 最小只測到 **414px**，而且只看卡片與彈窗、**沒有量表單區塊**，
所以這些問題它一個都沒抓到。新的檢查在 **402（使用者的寬度）／390／360／834／1440** 五個尺寸上量：

- 沒有橫向溢出（並列出超出畫面的元素）
- 「發佈比賽」按鈕沒有被壓成細條（所有尺寸都驗：寬 ≥ 88px）
- 手機上該按鈕是整條（≥ 60% 視窗寬）且高度正常（32～80px）
- 「報名開始／截止」都在卡片內、且是整條（≥ 60% 視窗寬）
- 篩選列日期欄位有標籤可辨識
- 沒有任何文字按鈕被壓成比 44px 窄
- 每個表單欄位都有標籤或說明（沒有「無名欄位」）
- 過程中沒有前端例外

（依使用者指示：這支**不寫任何截圖檔**，報告只給數字。）

## 變更檔案

- `public/index.html`：送出列改為手機堆疊、兩欄網格加響應式前綴、篩選日期加標籤、
  表單欄位補 `for=`／`aria-label`（`#category`／`#date`／`#end_date`／`#start_hour`／
  `#start_minute`／`#end_hour`／`#end_minute`／`#filterCategory`／`#filterTag`）、
  地圖連結提示縮短避免被截斷。
- `public/css/custom.css`（手機區塊）：標題不折行、身份標籤縮短、
  `button[data-action]` 最小寬度 44px、送出按鈕最小高度 40px。
- `tests/browser/mobile-layout-check.js`（新，39 項）＋納入 `npm run check:browser`（24→**25 支**）。
